# 맵 선택과 상황별 음악 구성

> 이 글은 주간 작업을 주제별로 나누어 정리한 회고다. 게시 날짜는 개별 기능의 실제 구현일과 다를 수 있다.

기존 테스트 맵에 더해 새로운 맵을 제작했다.
조명을 학습하면서 새 맵의 밤 버전도 구성했고, 선택 가능한 맵이 늘어나면서 맵 선택 UI를 추가했다.

## 맵 정의와 선택 목록 연결

맵 정의 데이터에는 선택 화면에 필요한 정보를 모았다.

| 정보 | 용도 |
|---|---|
| 미리보기 이미지 | 선택할 맵의 모습 표시 |
| 맵 참조 | 실제로 사용할 맵 지정 |
| 표시 이름 | 선택 UI에 보여 줄 이름 |

정의 데이터를 설정하고 `ComboBox String`의 선택 목록에 항목을 추가하면 해당 맵을 선택할 수 있도록 연결했다.
새 맵을 추가할 때는 맵 정의와 선택 목록을 함께 설정하는 방식이다.

같은 공간도 조명에 따라 인상이 달라졌다.
낮과 밤 버전을 구성하면서 맵의 형태뿐 아니라 실제 플레이 화면에서 보이는 분위기도 함께 조정했다.

## 맵별 음악을 관리하는 액터

플레이 화면에 음악이 없어 전체적으로 심심하게 느껴졌다.
처음에는 컨트롤러에 음악 재생 컴포넌트를 붙이는 방식을 생각했지만, 맵마다 다른 음악을 설정할 수 있도록 별도 액터를 배치했다.

액터에는 타이틀, 게임 시작, 게임 종료 등 상황별 음원을 설정했다.
`GameState`의 상태 변경을 델리게이트로 전달받아 각 클라이언트에서 해당 상황에 맞는 음원을 2D로 재생하도록 구성했다.

```text
GameState 상태 변경
    ↓ 델리게이트로 전달
상황에 맞는 음원 선택
    ↓
각 클라이언트에서 2D 음악 재생
```

맵에 배치된 액터에서 음원을 바꿀 수 있어 맵마다 다른 분위기를 설정하기 편해졌다.
이번 작업은 게임 진행 상태에 맞춰 배경 음악을 바꾸는 흐름에 집중했다.

## 에디터 안에서 음원 편집

음원 수정에는 언리얼의 Waveform Editor 플러그인을 활용했다.
외부 편집 프로그램으로 옮기는 과정 없이 에디터 안에서 음원을 수정하고 바로 적용할 수 있었다.

맵을 실행해 음악을 들어 보고 다시 수정하는 과정을 에디터 안에서 이어갈 수 있었다.
